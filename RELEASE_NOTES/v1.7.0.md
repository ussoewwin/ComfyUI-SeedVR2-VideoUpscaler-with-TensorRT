# SeedVR2 Video Upscaler — Release Notes (v1.7.0)

## Overview

SeedVR2 Video Upscaler v1.7.0 introduces the **Resolution Grid Alignment Architecture (`alignment_mode`)**, providing users and pipeline engineers with granular, deterministic control over how arbitrary aspect ratios and non-standard video resolutions are aligned to the underlying spatial divisibility grid.

In generative video diffusion models like SeedVR2, spatial dimensions must conform to strict divisible grids dictated by the 3D VAE spatial compression ratio (8×) and DiT patchification (2×), requiring all spatial tensors to be multiples of 16 ($8 \times 2 = 16$). Previously, pipelines either forced reflection padding (which preserves exact dimensions losslessly but can occasionally produce boundary artifacts on sensitive aspect ratios) or enforced upstream center-cropping (which completely prevents padding artifacts but irreversibly truncates boundary pixels). 

v1.7.0 resolves this trade-off by introducing the `alignment_mode` input parameter on the `SeedVR2 Video Upscaler` node with four distinct alignment strategies: **`pad (lossless)`** (default), **`crop_16`** (upstream SeedVR2 behavior), **`crop_32`**, and **`crop_64`**.

---

## 1. Technical Background & Architectural Motivation

### 1.1 The Spatial Divisibility Constraint

The SeedVR2 inference pipeline combines two spatially constrained neural architectures:
1. **3D Causal VAE (Encoder / Decoder)**: Employs an $8\times$ spatial downsampling factor ($H \times W \to \frac{H}{8} \times \frac{W}{8}$). Any dimension not divisible by 8 causes fractional latent dimensions or spatial shape mismatches during un-pooling/tiled convolutions.
2. **Diffusion Transformer (DiT)**: Operates on patchified latent tokens with a patch size of $2 \times 2$. Consequently, the latent representations must be divisible by 2, elevating the total spatial divisibility constraint of the input video to $\text{LCM}(8, 2) = 16$ pixels.

When upscaling videos with non-standard dimensions (such as mobile portrait 560×938, legacy SD 720×480, or arbitrary custom crops), the resized intermediate dimensions frequently produce remainder pixels:
$$\text{remainder}_w = W \pmod{16}, \quad \text{remainder}_h = H \pmod{16}$$

### 1.2 Trade-offs Between Reflection Padding and Center Cropping

- **Reflection Padding (`DivisiblePad`)**:
  Appends mirror reflections of border pixels to expand the frame to the next multiple of 16, and crops back to the target resolution after VAE decoding. While this achieves pixel-perfect dimension preservation without altering the framing, reflection padding on custom aspect ratios can occasionally cause boundary discontinuities or interact adversely with DiT 720P window attention (manifesting as faint boundary artifacts or localized noise).
- **Center Cropping (`DivisibleCrop`)**:
  Truncates odd remainder dimensions to the nearest smaller multiple of 16 symmetrically from the center. Because the model processes authentic, native image content across all edges without artificial padding, border reflection noise and boundary artifacts are completely eliminated. However, up to 15 pixels are discarded along each axis, altering the exact output resolution and aspect ratio.

---

## 2. The `alignment_mode` Architecture & Modes

To give users complete control over this trade-off, the `SeedVR2 Video Upscaler` node introduces the `alignment_mode` dropdown selector with four operational modes:

| Mode | Spatial Alignment Operator | Boundary Padding | Dimension Preservation | Recommended Use Case |
|---|---|---|---|---|
| **`pad (lossless)`** *(Default)* | `DivisiblePad((16, 16))` | Yes (Reflection) | 100% Exact (Lossless un-padding) | Standard upscaling, exact framing & aspect ratio preservation |
| **`crop_16`** | `DivisibleCrop((16, 16))` | None | Truncates to nearest $\le 16n$ | Custom/unusual aspect ratios where padding produces edge artifacts |
| **`crop_32`** | `DivisibleCrop((32, 32))` | None | Truncates to nearest $\le 32n$ | Multi-stage workflows, video encoders requiring 32-pixel macroblocks |
| **`crop_64`** | `DivisibleCrop((64, 64))` | None | Truncates to nearest $\le 64n$ | Hardware-accelerated pipelines, strict 64-byte aligned execution |

### 2.1 Mode Details

#### 1. `pad (lossless)` (Default)
- **Pipeline**: `NaResize` $\to$ `DivisiblePad((16, 16), safe_padding=safe_padding)` $\to$ Phase 1 Encode $\to$ Phase 2 DiT Upscale $\to$ Phase 3 VAE Decode $\to$ Phase 4 Post-process Spatial Unpad (`[:true_h, :true_w]`).
- **Characteristics**: Preserves the exact user-specified target dimensions down to a single pixel. Coordinates seamlessly with `safe_padding` to eliminate window attention runt slivers ($< 6$ latent px) on custom resolutions.

#### 2. `crop_16` (Original Upstream SeedVR2 Behavior)
- **Pipeline**: `NaResize` $\to$ `DivisibleCrop((16, 16))` $\to$ Phase 1 Encode $\to$ Phase 2 DiT Upscale $\to$ Phase 3 VAE Decode $\to$ Phase 4 Post-process (no unpadding needed).
- **Characteristics**: Matches the byte-for-byte behavior of the official ByteDance / NumZ SeedVR2 codebase. By completely omitting padding, it guarantees zero synthetic boundary noise on arbitrary non-standard aspect ratios.

#### 3. `crop_32` / `crop_64`
- **Pipeline**: `NaResize` $\to$ `DivisibleCrop((k, k))` where $k \in \{32, 64\}$.
- **Characteristics**: Enforces strict higher-order power-of-two divisibility. Eliminates edge padding while ensuring that downstream video codecs (e.g. HEVC/AV1 encoding, NVENC hardware blocks) or secondary post-processing models receive perfectly aligned tensor dimensions without re-scaling.

## 3. Implementation Details & Integration

### 3.1 Node Interface Registration (`src/interfaces/video_upscaler.py`)
```python
io.Combo.Input("alignment_mode",
    options=["pad (lossless)", "crop_16", "crop_32", "crop_64"],
    default="pad (lossless)",
    optional=True,
    tooltip=(
        "How to align video dimensions to model grid (default: 'pad (lossless)').\n"
        "• 'pad (lossless)': Lossless reflection padding to 16-multiple, restored after decoding.\n"
        "• 'crop_16': Original SeedVR2 behavior. Automatically truncates odd dimensions to the nearest multiple of 16 (center crop).\n"
        "  Completely eliminates edge noise/artifacts on non-standard aspect ratios by eliminating padding.\n"
        "• 'crop_32': Truncates odd dimensions to multiple of 32 (center crop).\n"
        "• 'crop_64': Truncates odd dimensions to multiple of 64 (center crop)."
    )
)
```

### 3.2 Dynamic Pipeline Construction (`src/core/generation_utils.py`)
```python
if alignment_mode.startswith("crop"):
    try:
        crop_factor = int(alignment_mode.split("_")[1])
    except (IndexError, ValueError):
        crop_factor = 16
    divisible_transform = DivisibleCrop((crop_factor, crop_factor))
else:
    divisible_transform = DivisiblePad((16, 16), safe_padding=safe_padding)

return Compose([
    NaResize(
        resolution=resolution,
        mode="side",
        downsample_only=False,
        max_resolution=max_resolution,
    ),
    Lambda(lambda x: torch.clamp(x, 0.0, 1.0)),
    divisible_transform,
    Normalize(0.5, 0.5),
    Lambda(lambda x: x.permute(1, 0, 2, 3)),
])
```

### 3.3 Target Dimension Tracking & Phase 4 Restoration
- In `setup_video_transform()`, if a crop mode is selected, `true_target_dims` is calculated directly from the cropped dimensions (`true_h, true_w = resized_sample.shape[-2:]`), bypassing un-padding in Phase 4.
- In `pad (lossless)` mode, `true_target_dims` records the post-resize, pre-padded dimensions, and Phase 4 post-processing cleanly slices the output buffer back to `[:true_h, :true_w]`.
