# SpargeAttn-hswq — DiT 新增块稀疏注意力后端

---

## 1. 概述

v1.5.9 新增注意力后端 **`spargeattn`**，基于 [`SpargeAttn-hswq`](https://github.com/ussoewwin/SpargeAttn-hswq) fork（`spas_sage_hswq_attn` v1.0.0）。它在 SageAttention2++ 量化内核（QK INT8 + PV FP8）之上运行**两阶段块稀疏过滤**，使用该 fork 即插即用的入口 `spas_sage2_attn_meansim_topk_cuda` —— 即论文内核基准中的 "SpargeAttn + Sage2" 组合。

注意力是 DiT 中的主要计算量：每个变换器块都要对 vid+txt 拼接 token 序列做注意力。SpargeAttn 会跳过 softmax 贡献可忽略的注意力块，用用户可选择的精度换速度。

| 注意力模式 | 内核 | 精度 | 稀疏性 |
|---|---|---|---|
| `sdpa` | PyTorch SDPA | FP16/BF16 精确 | 无 |
| `sageattn_2` | SageAttention2 | QK INT8 + PV FP8 | 无 |
| **`spargeattn`**（新增） | **SpargeAttn-hswq** | **QK INT8 + PV FP8 + 块跳过** | **topK 可调** |

Windows 预构建 wheel：[https://huggingface.co/ussoewwin/Sage-Attention-and-Sparge-Attention-HSWQ](https://huggingface.co/ussoewwin/Sage-Attention-and-Sparge-Attention-HSWQ)

---

## 2. 为什么是两阶段块稀疏过滤

SageAttention2++ 已将 Q/K 量化为 INT8、P/V 量化为 FP8（按块）。SpargeAttn 在此之上增加了**块选择阶段**：

1. **第一阶段（粗算）：** 低精度注意力前向（FP8 PV）计算 KV 网格上各块的近似重要性分数。
2. **第二阶段（topK）：** 仅按 softmax 贡献累计排序选出前 `K` 比例的 KV 块，用全精度路径重算，其余块完全跳过。

保留比例以 **`sparge_topk`** 暴露给用户（`1.0` = 全部计算，越小跳过越多、越快）。

## 3. 感知变长的逐窗口执行

**目标文件：** `src/optimization/compatibility.py`
**目标函数：** `call_sparge_attn_varlen()`（L606–684）

SeedVR2 不会在单一平铺序列上调用注意力。vid 与 txt token 流打包为变长批次，MSA / Swin 窗口注意力都按 `cu_seqlens` 逐窗口循环。SpargeAttn 即插即用 API 不原生支持 varlen，因此实现了仿照 `pytorch_varlen_attention()` 的逐窗口分发：

```python
def call_sparge_attn_varlen(q, k, v, cu_seqlens_q, cu_seqlens_k,
                            max_seqlen_q, max_seqlen_k,
                            sparge_topk: float = 0.5, **kwargs):
    # ...
    output = torch.empty_like(q)
    for i in range(num_seqs):
        q_start, q_end = int(cu_q_cpu[i]), int(cu_q_cpu[i + 1])
        k_start, k_end = int(cu_k_cpu[i]), int(cu_k_cpu[i + 1])
        q_i = q[q_start:q_end].permute(1, 0, 2).unsqueeze(0)  # (1, H, S, D)
        k_i = k[k_start:k_end].permute(1, 0, 2).unsqueeze(0)
        v_i = v[k_start:k_end].permute(1, 0, 2).unsqueeze(0)

        seq_len = q_i.size(-2)
        headdim = q_i.size(-1)
        if seq_len < 128 or headdim not in (64, 128):
            out_i = _sdpa(q_i, k_i, v_i, is_causal=is_causal)       # 精确回退
        else:
            out_i = spas_sage2_attn_meansim_topk_cuda(               # SpargeAttn 内核
                q_i, k_i, v_i, topk=_topk, is_causal=is_causal, tensor_layout="HND",
            )
        output[q_start:q_end] = out_i.squeeze(0).permute(1, 0, 2)

    return output.to(out_dtype) if output.dtype != out_dtype else output
```

关键实现细节：

| 方面 | 处理方式 |
|---|---|
| 输出缓冲区 | 预分配 `torch.empty_like(q)`；每个窗口直接写入自己的切片（无列表暂存、无最终 `torch.cat`） |
| 输入打包 | `(total_seq, heads, head_dim)` → 每窗口 `(1, H, S, D)`，即内核要求的 `"HND"` 张量布局 |
| dtype | 内核要求 FP16/BF16；输入归一化（K/V 转为 Q 的 dtype；Q 为 FP32 时全部转 BF16），输出最后转回调用方 dtype |
| 因果性 | `is_causal` 同时转发给内核与 SDPA 回退 |

---

## 4. 逐窗口约束回退（绝不静默）

SpargeAttn 内核对输入有硬性断言，而 SeedVR2 的可变窗口并不总能满足。每个窗口在内核分发**之前**检查，不满足的窗口透明回退到精确 SDPA：

| 约束 | 原因 | 回退 |
|---|---|---|
| `seq_len >= 128` | 内核断言：块稀疏池化要求每窗口至少 128 token | 该窗口使用精确 SDPA |
| `headdim ∈ {64, 128}` | 内核断言（SeedVR2 为 128，实际恒满足） | 该窗口使用精确 SDPA |
| topk ∉ `(0, 1]` | 无效保留比例 | 净化为 `0.5` |

小分辨率输入会出现短窗口（空间窗口缩小到 128 token 以下）。回退保证**内核无法运行之处结果精确**、能运行之处享受稀疏加速 —— 输出是按窗口形状确定性选择的“精确 + 块稀疏”混合。

## 5. 可用性与回退链

**目标函数：** `validate_attention_mode()`（L273–298）

```
requested_mode = 'spargeattn'
    ├─ 已安装 spas_sage_hswq_attn  → 'spargeattn'（块稀疏内核）
    ├─ 否则已安装 SageAttention2   → 'sageattn_2'（量化、无稀疏）
    └─ 否则                        → 'sdpa'（精确）
```

回退时输出带 wheel 安装链接的 WARNING 日志 —— 绝不静默。同一回退链在 `FlashAttentionVarlen`（共享入口）中同样生效，CLI 与节点路径行为一致。

## 6. topK 可调

### 节点路径（DiT 加载器）

`SeedVR2 Load DiT Model` 新增可选 COMBO 输入 **`sparge_topk`**（`src/interfaces/dit_model_loader.py` L121–132）：

- 选项：`0.05` … `1.0`（0.05 步进），**默认 `0.5`**
- 越高 = 计算越多 KV 块 = 越精确、加速越少；`1.0` = 不跳过任何块
- 其他注意力后端忽略该输入

### CLI 路径

`--attention_mode spargeattn` + `--sparge_topk`（`inference_cli.py` L1480–1483，默认值与范围相同）。

### 传递与净化

`src/core/model_configuration.py` 将该值端到端传递并用 `_safe_topk()` 净化：`(0, 1]` 之外的任何值（含非数值）一律回退 `0.5`。净化后的值在模型（重新）配置时应用到全部注意力模块，缓存命中时重新应用 —— 切换模型或注意力模式不会残留过期的 topK。

## 7. 验证

RTX 5060 Ti（SM120，torch 2.14.1+cu132）GPU 实测：

- **混合窗口变长调用（256 + 64 token）：** 256 token 窗口返回 SpargeAttn 量化输出；不足 128 的窗口回退 SDPA，与精确参考 **余弦相似度 1.000000**。
- **端到端：** 通过真实 DiT 注意力模块（`src/models/dit_3b/attention.py` / `dit_7b/attention.py`）验证 `FlashAttentionVarlen(attention_mode='spargeattn')`，确认 `sparge_topk` 值到达内核。
- `dit_3b` 与 `dit_7b` 的注意力模块在 SpargeAttn 分发上保持字节一致。
