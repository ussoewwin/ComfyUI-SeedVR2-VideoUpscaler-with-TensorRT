# SeedVR2 Video Upscaler — 版本发布说明 (v1.7.1)

## 概述

SeedVR2 Video Upscaler v1.7.1 将 **TensorRT RTX 执行栈** 更新至 NVIDIA 当前发布的版本。

此前的依赖栈将 `tensorrt-rtx` 固定在 1.6.1.120。本次发布将运行时升级至 **1.7.1.116**，并同步更新 `onnx`、`onnxscript` 与 `polygraphy`。同时修正了安装脚本：此前仅检测模块能否导入，导致当已安装旧版本时，`requirements-windows-cu132.txt` 中的固定版本会被静默忽略。

> **重要 — 既有 TensorRT 引擎必须重新构建。**
>
> TensorRT `.rtxplan` 引擎与构建它的 TensorRT 版本绑定。使用 `tensorrt-rtx` 1.6.1 序列化的引擎 **无法被 1.7.1 反序列化**，尝试运行时会报如下错误：
>
> ```
> IRuntime::deserializeCudaEngine: Error Code 1: Serialization
> (Serialization assertion stdVersionRead == kSERIALIZATION_VERSION failed.
>  Version tag does not match. Note: Current Version: 100, Serialized Engine Version: 98)
> ```
>
> 升级后需使用 **`SeedVR2 Build TensorRT VAE Engines`** 节点（或 `scripts/prepare_tensorrt.py`）重新构建 `tensorrt_backend/artifacts/` 下的全部引擎。在新引擎验证通过之前请保留原有文件，因为本次升级与旧版序列化的 plan 不向后兼容。

---

## 1. 依赖更新

| 包名 | 原版本 | 更新后 |
|---|---|---|
| `tensorrt-rtx` | 1.6.1.120 | **1.7.1.116** |
| `onnx` | 1.22.0 | **1.23.2** |
| `onnxscript` | 0.7.1 | **0.7.2** |
| `polygraphy` | 0.53.4 | **0.53.6** |

`triton-windows` 维持不锁定版本，以匹配当前安装的 PyTorch 构建。

### 1.1 为何 TensorRT RTX 升级会导致引擎必须重建

TensorRT 在序列化引擎时会写入内部归档版本标记。运行时拒绝加载标记不匹配的 plan，且不存在就地迁移路径。因此「磁盘上存在引擎」与「当前运行时可用」这两件事必须显式区分：

- `src/core/trt_encoder.py` 与 `src/core/trt_decoder.py` 中的 `find_engine_path()` 仅按文件名与大小解析引擎。
- 反序列化随后在 `_engine()` 中进行；版本不匹配时 `deserialize_cuda_engine()` 返回 `None`，加载器抛出 `Could not deserialize TensorRT encoder/decoder: <path>`。

由于文件名依旧匹配，失效引擎会持续被选中，直至其被重新构建或删除。通过 **`SeedVR2 Build TensorRT VAE Engines`** 节点重建会原地覆盖该文件，从而消除版本不匹配。

## 2. 安装脚本修正（`install.py`）

### 2.1 问题

`ensure_package()` 仅通过导入来校验环境：

```python
def ensure_package(import_name: str, install_name: str | None = None, no_deps: bool = True) -> None:
    try:
        __import__(import_name)
        return
    except ImportError:
        pass
    ...
```

任何可导入的版本都会通过检查。当已安装旧版 `tensorrt-rtx`、`onnx`、`onnxscript` 或 `polygraphy` 时，固定版本约束被无提示跳过，运行时栈与 `requirements-windows-cu132.txt` 不一致。

### 2.2 修正

现将固定版本显式传入 `pip`：

```python
ensure_package("tensorrt_rtx", "tensorrt-rtx==1.7.1.116", no_deps=True)
# Linux: triton / Windows: triton-windows (no version pin; match installed torch)
ensure_package("triton", "triton-windows" if sys.platform.startswith("win") else "triton", no_deps=True)
ensure_package("onnx", "onnx==1.23.2", no_deps=True)
ensure_package("onnxscript", "onnxscript==0.7.2", no_deps=True)
ensure_package("polygraphy", "polygraphy==0.53.6", no_deps=True)
```

`requirements-windows-cu132.txt` 中承载相同的版本约束，使全新安装与就地升级收敛到完全一致的版本。

## 3. 升级步骤

1. **更新节点包** 至 v1.7.1（Manager 更新，或在 custom node 目录执行 `git pull`）。
2. **安装新的依赖栈**：
   ```
   pip install -r requirements-windows-cu132.txt
   ```
   或由 ComfyUI 下次启动时运行的 `install.py` 完成。
3. **重新构建 TensorRT VAE 引擎。** 对计划使用的每种帧数 / 分块尺寸组合，运行一次 **`SeedVR2 Build TensorRT VAE Engines`** 节点。使用 1.6.1 构建的引擎在 1.7.1 上不可用。
4. **验证** 重建后的 plan 能够成功反序列化，再开始正式生成。版本不匹配会在 Phase 1 立即以 `Could not deserialize TensorRT encoder` 暴露。

> **关于引擎范围：** 仅你实际重建的帧数与分块尺寸可用。若 `engine_tile` 保持 `auto`，加载器会优先选择磁盘上可用的最大分块（1024 → 768 → 512 → 256），因此遗留的旧大分块引擎仍会被优先选中，排在刚重建的小分块之前。重建期间请显式固定 `engine_tile`，或删除已过期的 plan。

## 4. 兼容性

- 节点输入、输出与工作流 JSON 均无变更，既有工作流可直接加载。
- `src/` 除依赖版本约束与安装脚本外无改动。
- 本次发布序列化的引擎需要 `tensorrt-rtx` 1.7.1 或更新版本，1.6.1 无法读取。
