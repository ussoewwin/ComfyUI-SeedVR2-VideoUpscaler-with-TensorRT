# SeedVR2 Video Upscaler — 版本发布说明 (v1.6.5)

## 概述

SeedVR2 Video Upscaler v1.6.5 重点修复了 VAE 推理流水线中由于单端连接或独立标志脱落导致的意外回退至标准 PyTorch FP16 VAE 问题，彻底消除了在高分辨率（如 4208px）下引发的严重 CUDA 显存溢出（OOM）崩溃。此外，本版本在 TensorRT 引擎构建节点中引入了构建完成后自动清理中间 ONNX 文件的机制，大幅节约磁盘空间。

---

## 1. 彻底清除 PyTorch FP16 VAE 意外回退路径

### 根本原因与技术缺陷分析
在以往版本中，`SeedVR2VideoUpscaler` 节点对外暴露了独立的 `vae_encode` 与 `vae_decode` 输入端。当工作流中仅连接了其中一个端口（例如仅将 TensorRT VAE 加载器连接到 `vae_decode`，而未连接 `vae_encode`）时，`encode_cfg` 会被解析为空字典（`{}`）：
- `runner.use_tensorrt_vae_encode` 被置为 `False`。
- 历史代码中的独立标志解耦逻辑（`# TRT decoder + FP16 encoder must keep the encoder on the FP16 path`）允许编码器静默脱离 TensorRT 链路。
- 导致 Phase 1（VAE 编码）绕过专用 TensorRT 1-shot 引擎，意外掉落回退至 PyTorch FP16 VAE（`VideoAutoencoderKLWrapper`）。

在两阶段超分辨率流水线等超高分辨率场景下（例如 `2160x2160px` 填充至 `4208x4208px`），PyTorch VAE 采用无切片的 3D 因果卷积（`InflatedCausalConv3d`）执行全局计算，在切片拼接阶段尝试分配超过 30.69 GiB 显存（已分配 26.47 GiB + 请求 4.22 GiB），直接导致 16GB 显卡发生 CUDA 显存溢出（OOM）。

### 技术修复方案
1. **双向配置同步（Bidirectional Mirroring）**：
   无论用户仅连接了 `vae_encode` 还是 `vae_decode`，节点会自动在两端之间双向同步完整的 VAE 配置，避免未连接端掉入空字典：
   ```python
   encode_cfg = dict(vae_encode) if vae_encode is not None else (dict(vae_decode) if vae_decode is not None else {})
   decode_cfg = dict(vae_decode) if vae_decode is not None else (dict(vae_encode) if vae_encode is not None else {})
   ```
2. **强制 TensorRT 状态一致锁定**：
   只要编码或解码端任一端启用了 TensorRT，双端均强制锁定为 TensorRT 路径，并严格同步 Runner 的全部运行时标志：
   ```python
   _is_trt = bool(
       encode_cfg.get("use_tensorrt_vae", False)
       or decode_cfg.get("use_tensorrt_vae", False)
       or encode_cfg.get("vae_backend") == "tensorrt"
       or decode_cfg.get("vae_backend") == "tensorrt"
   )
   if _is_trt:
       encode_cfg["use_tensorrt_vae"] = True
       encode_cfg["vae_backend"] = "tensorrt"
       decode_cfg["use_tensorrt_vae"] = True
       decode_cfg["vae_backend"] = "tensorrt"
   
   runner.use_tensorrt_vae_encode = _is_trt
   runner.use_tensorrt_vae_decode = _is_trt
   runner.use_tensorrt_vae = _is_trt
   ```
3. **推理阶段双重断言（`src/core/infer.py`）**：
   在 `VideoDiffusionInfer.vae_encode()` 与 `vae_decode()` 中，强化了 `_enc_trt` 与 `_dec_trt` 的多重状态检查，确保只要处于 TensorRT 模式下，直接调用 dedicated TensorRT 引擎，彻底切断向 PyTorch FP16 的静默回退。

## 2. 引擎构建完成后自动清除中间 ONNX 临时文件

在使用 `SeedVR2BuildTensorRTVAE`（`src/interfaces/trt_vae_builder.py`）节点或加载器动态编译（`src/interfaces/trt_vae_model_loader.py`）构建专用 TensorRT RTX 引擎时：
- 追踪大 batch 视频图会生成中间临时文件 `.onnx` 及 `.onnx.data`。
- 虽然这些文件是 `cloud_build_engine.py` 的必要输入，但一旦最终的 `.rtxplan` 引擎序列化完成，中间 ONNX 文件即失去使用价值。
- **自动物理删除**：引擎构建成功后，程序会立即自动调用 `unlink()` 彻底删除 `onnx_path` 与对应的 `.onnx.data`，防止单次构建残留数 GB 的临时文件占用宝贵的磁盘空间。

## 3. 节点显示名称规范化

- 移除了 `SeedVR2VideoUpscaler` 节点注册时的历史版本号后缀，规范统一显示为 `SeedVR2 Video Upscaler`。
- 100% 保持节点 ID 及输入输出 Schema 兼容，现有工作流无缝加载。

## 4. 变更文件与影响范围

- `src/interfaces/video_upscaler.py`：双向 VAE 配置镜像与 TRT 标志严格锁定。
- `src/core/infer.py`：编码/解码阶段 TRT 多标志严格断言。
- `src/interfaces/trt_vae_builder.py`：引擎生成完毕后自动物理删除中间 ONNX 文件。
- `src/interfaces/trt_vae_model_loader.py`：加载器引擎构建路径中自动物理删除中间 ONNX 文件。
- `md/changelog.md` 与 `zhmd/changelogzh.md`：中英文更新日志双向同步。
