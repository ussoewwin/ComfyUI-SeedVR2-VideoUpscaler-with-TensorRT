# SeedVR2 Video Upscaler — 版本发布说明 (v1.7.0)

## 概述

SeedVR2 Video Upscaler v1.7.0 引入了**分辨率网格对齐架构 (`alignment_mode`)**，为用户与管线工程人员提供了对任意宽高比与非标分辨率如何对齐底层空间整倍数网格的精确、可控机制。

在 SeedVR2 这类生成式视频扩散模型中，受 3D VAE 空间下采样比率（8×）与 DiT Patch 切分尺寸（2×）的底层约束，所有输入空间张量必须严格满足 16 像素的整除对齐（$\text{LCM}(8, 2) = 16$）。此前，管线要么强制采用镜像反射填充（能够 100% 无损保留原始尺寸，但在特定长宽比下可能因边界不连续而引入边缘微弱瑕疵），要么沿用上游的原生居中裁剪（彻底杜绝填充瑕疵，但不可逆地裁切掉边缘像素）。

v1.7.0 通过在 `SeedVR2 Video Upscaler` 节点上新增 `alignment_mode` 输入参数，彻底化解了这一权衡痛点，提供四种清晰的对齐策略：**`pad (lossless)`**（默认无损填充）、**`crop_16`**（上游 SeedVR2 原生默认行为）、**`crop_32`** 以及 **`crop_64`**。

---

## 1. 技术背景与架构动机

### 1.1 空间整除约束的数学与模型机理

SeedVR2 的推理管线由两大具有严格空间整倍数约束的模型组成：
1. **3D 因果 VAE（编码器 / 解码器）**：采用 $8\times$ 空间下采样因子（$H \times W \to \frac{H}{8} \times \frac{W}{8}$）。若空间尺寸非 8 的整数倍，将在分块卷积或解池化操作中产生分数维度或张量形状不匹配。
2. **Diffusion Transformer (DiT)**：在潜空间中采用 $2 \times 2$ 的 Patch 划分。因此潜空间张量尺寸必须为 2 的整数倍。两者结合，输入视频的空间对齐约束提升为：
   $$\text{LCM}(8, 2) = 16\text{ 像素}$$

在放大非标准尺寸视频（如手机竖屏 560×938、传统标清 720×480、或用户自定义裁切画面）时，缩放后的目标尺寸往往存在余数像素：
$$\text{remainder}_w = W \pmod{16}, \quad \text{remainder}_h = H \pmod{16}$$

### 1.2 镜像填充与居中裁剪的技术权衡

- **反射填充 (`DivisiblePad`)**：
  通过边缘镜像填充将画面补齐至最近的 16 倍数，并在 VAE 解码后按目标尺寸裁切还原。虽然实现了精确到单个像素的无损尺寸保留，但在部分特殊非标比例下，反射边缘可能破坏画面上下文连续性，或在 DiT 720P 窗口自注意力切分中产生细微边缘伪影。
- **居中裁剪 (`DivisibleCrop`)**：
  从画面中心对称向外截取至最近的 16 整数倍尺寸，丢弃边缘的零碎像素。由于模型全流程处理的均为原生画面内容、不引入任何合成填充区域，彻底杜绝了边界反射瑕疵与边缘噪声。但缺点是长宽方向最多会被裁切掉 15 个像素，微调了原始宽高比。

## 2. `alignment_mode` 对齐架构与模式解析

为了让用户根据具体内容自由选择最优策略，`SeedVR2 Video Upscaler` 节点新增了 `alignment_mode` 组合选择控件：

| 模式 | 空间对齐算子 | 边界填充 | 尺寸保留特性 | 推荐应用场景 |
|---|---|---|---|---|
| **`pad (lossless)`** *(默认)* | `DivisiblePad((16, 16))` | 有（镜像反射） | 100% 绝对无损（解码后还原） | 标准超分辨率放大、对画面构图与精确像素尺寸有严格要求的场景 |
| **`crop_16`** | `DivisibleCrop((16, 16))` | 无（直接裁剪） | 截断至最近的 $\le 16n$ 尺寸 | 边缘出现反射瑕疵的特殊长宽比、追求与上游原生 SeedVR2 行为一致 |
| **`crop_32`** | `DivisibleCrop((32, 32))` | 无（直接裁剪） | 截断至最近的 $\le 32n$ 尺寸 | 多阶段串联工作流、下游视频编码器（如 HEVC/AV1 宏块）对齐需求 |
| **`crop_64`** | `DivisibleCrop((64, 64))` | 无（直接裁剪） | 截断至最近的 $\le 64n$ 尺寸 | 硬件加速流水线、严格要求 64 字节内存/张量对齐的执行环境 |

### 2.1 各模式技术运行机制

#### 1. `pad (lossless)`（默认无损模式）
- **处理链路**：`NaResize` $\to$ `DivisiblePad((16, 16), safe_padding=safe_padding)` $\to$ Phase 1 编码 $\to$ Phase 2 DiT 超分 $\to$ Phase 3 VAE 解码 $\to$ Phase 4 后处理还原裁剪（`[:true_h, :true_w]`）。
- **技术特性**：完全保留原生画面的所有像素，不丢失任何边缘构图。可与 `safe_padding` 联动，动态消除 DiT 720P 极小残余窗口切片（$< 6$ 潜像素）产生的边缘棋盘格噪声。

#### 2. `crop_16`（上游 SeedVR2 原生默认行为）
- **处理链路**：`NaResize` $\to$ `DivisibleCrop((16, 16))` $\to$ Phase 1 编码 $\to$ Phase 2 DiT 超分 $\to$ Phase 3 VAE 解码 $\to$ Phase 4 输出（无需还原裁切）。
- **技术特性**：与 ByteDance / NumZ 官方 SeedVR2 原生代码保持 100% 字节一致。全流程无任何填充像素，彻底根除任何由填充边界引发的自注意力计算异常。

#### 3. `crop_32` / `crop_64`（高阶网格整除模式）
- **处理链路**：`NaResize` $\to$ `DivisibleCrop((k, k))`（$k \in \{32, 64\}$）。
- **技术特性**：强制执行更高阶的 2 的幂次对齐。在免除填充区域的同时，确保后续接入的视频编码器（如 NVENC 硬件编码块）或多尺度后处理节点能够直接获取严苛对齐的张量规格，避免二次缩放。

## 3. 核心实现与工程集成

### 3.1 节点参数定义 (`src/interfaces/video_upscaler.py`)
```python
io.Combo.Input("alignment_mode",
    options=["pad (lossless)", "crop_16", "crop_32", "crop_64"],
    default="pad (lossless)",
    optional=True,
    tooltip=(
        "How to align video dimensions to model grid (default: 'pad (lossless)').\n"
        "• 'pad (lossless)': Lossless reflection padding to 16-multiple, restored after decoding.\n"
        "• 'crop_16': Original SeedVR2 behavior. Automatically truncates odd dimensions to the nearest multiple of 16 (center crop).\n"
        "  Completely eliminates edge noise/artifacts on non-standard aspect ratios by eliminating padding.\n"
        "• 'crop_32': Truncates odd dimensions to multiple of 32 (center crop).\n"
        "• 'crop_64': Truncates odd dimensions to multiple of 64 (center crop)."
    )
)
```

### 3.2 动态转换管线构建 (`src/core/generation_utils.py`)
```python
if alignment_mode.startswith("crop"):
    try:
        crop_factor = int(alignment_mode.split("_")[1])
    except (IndexError, ValueError):
        crop_factor = 16
    divisible_transform = DivisibleCrop((crop_factor, crop_factor))
else:
    divisible_transform = DivisiblePad((16, 16), safe_padding=safe_padding)

return Compose([
    NaResize(
        resolution=resolution,
        mode="side",
        downsample_only=False,
        max_resolution=max_resolution,
    ),
    Lambda(lambda x: torch.clamp(x, 0.0, 1.0)),
    divisible_transform,
    Normalize(0.5, 0.5),
    Lambda(lambda x: x.permute(1, 0, 2, 3)),
])
```

### 3.3 尺寸追踪与 Phase 4 还原
- 在 `setup_video_transform()` 中，若选择裁剪模式，`true_target_dims` 将直接记录裁剪后的尺寸（`true_h, true_w = resized_sample.shape[-2:]`），在 Phase 4 中无需额外还原切片。
- 在 `pad (lossless)` 模式下，`true_target_dims` 记录缩放后、填充前的真实尺寸，Phase 4 后处理统一执行 `decoded_frames[..., :true_h, :true_w]` 完成无损还原。
