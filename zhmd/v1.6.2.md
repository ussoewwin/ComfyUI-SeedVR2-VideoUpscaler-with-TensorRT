# W4A8 × DisTorch2 完全适配 + 标准 DiT 加载器 norm_bf16（v1.6.1 以来）— v1.6.2

本版本是 **v1.6.1 以来的 W4A8 × DisTorch2 完全适配 + 标准 DiT 加载器 norm_bf16**。W4A8（`seedvr2_7b_convrot_w4a8.safetensors`）此前在 DisTorch2 CPU 卸载下仍有 467 MB（23 层）残留在 GPU 上——劣于 INT8/NVFP4——原因是打包尺寸计算漏算了 W4A8 的伴随 scale 张量。以下修正确立了明示的 layout-tag 判别使 W4A8 完全 CPU 卸载、与 INT8 的核心路径对齐、削减 Phase 2 峰值（rope/na 瞬态缓冲移除），并把 `norm_bf16`（v1.6.0 起仅 DisTorch2 节点）实装到标准加载器节点。

---

## 1. W4A8 伴随 scale 张量计入打包尺寸

**提交：** `d406dc1` — *fix(distorch2): count W4A8 companion scale tensors in packed size*；`bdf236e` — *refactor(w4a8): 拆分为专用 `_is_w4a8_quant` / `_w4a8_storage_bytes` 函数*

- **真因（实测）：** `src/core/distorch2_placement.py` 的 `_qt_storage_bytes()` 对 QuantizedTensor 只计 `_qdata`。W4A8 的 fp8 权重 scale（`_params.scale`，2.25 MB/层）与 `s_channel`（0.047 MB/层）保存在**独立 storage** 中，导致打包模型尺寸被少计 0.49 GB（报告 3.95 GB vs 实际 4.44 GB）。
- **后果：** DisTorch2 把 CPU 分配算小，23 层（467 MB）残留在 `cuda:0`——与 CPU 卸载目的相反（实测日志：`cpu 270 4075.42MB 89.7%` + `cuda:0 23 467.07MB 10.3%`）。
- 修正后逐层实测：W4A8 **20.30 MB**（`_qdata` 18.00 + scale 2.25 + s_channel 0.047）走专用路径；INT8 36.00 MB、NVFP4 18.00 MB 保持不变的通用路径；fp16 不变。

---

## 2. W4A8 以 layout tag 判别，不再用宽度启发式

**提交：** `7d1c391` — *fix(w4a8): identify W4A8 by layout tag, not width heuristic*

- **分离违反的修正：** 旧判别式 `_qdata.shape[1]*2 == weight.shape[1]` 对 **NVFP4 同样为真**（fp4 也是半宽），NVFP4 张量混入了 W4A8 专用路径。
- 现为明示判别：`_layout_cls == "AsymW4A8Int8Layout"`（tag 缺失时按 Params 特征回退）。3 种量化格式 + fp16 实测（真实 1 层，N=12288 K=3072）：

| 格式 | `_layout_cls` | is_w4a8 | storage 字节 |
| --- | --- | --- | --- |
| W4A8 | AsymW4A8Int8Layout | **True**（专用路径） | **20.30 MB** |
| INT8 | TensorWiseINT8Layout | False | 36.00 MB（通用路径） |
| NVFP4 | TensorCoreNVFP4Layout | **False**（修正前为 True） | 18.00 MB（通用路径） |
| fp16 | — | False | 72.00 MB（不变） |

---

## 3. DisTorch2 放置循环中的 W4A8 分支

**提交：** `6a216fc`、`78fad34`、`b5071cc` — *model-size accounting 加入 W4A8 处理 / placement 循环加入 W4A8 分支（伴随张量随迁 + 流式标志）/ 识别 w4a8·w4a4·w6a8 模型 tag 为量化*

- 放置循环经专用分支把 W4A8 伴随张量（`scale`、`s_channel`、`group_size`）与 `_qdata` 一并搬移，并设置流式标志。
- 模型名 tag `w4a8` / `w4a4` / `w6a8` 现与 `int8` / `nvfp4` 同样被识别为量化（`model_is_quantized`）。
- **待实机确认：** 打包尺寸现已正确记账（4.44 GB，此前少计为 3.95 GB），因此 CPU 分配可覆盖整个模型，修复前实测的 467 MB / 23 层 `cuda:0` 残留（cpu 89.7% + cuda:0 10.3%）预期归零。**尚未在实机 GPU 重新运行**——下次运行需在 `DisTorch2 Final Device/Layer Assignments` 日志中确认 `keep 0.00GB on cuda:0` / cpu 100%。

---

## 4. W4A8 与 INT8 核心路径对齐

**提交：** `0cb759c` — *quant_config {}（与 INT8 相同）以构造完全相同的 ops*；`7f64e3c` — *与 INT8 同一 autocast 路径（废除 W4A8 专属跳过；NVFP4 保持其跳过）*；`12ece89` — *强制 `_full_precision_mm` False（与核心 `_dit_quant_lock` 对齐）*

- W4A8 走与 INT8 完全相同的 autocast 路径（两者都是核心混合精度 Linear 上的 `quantize_input=False` 包）。只有 NVFP4 保留 autocast 跳过（其 CUDA 量化拒绝 float32 code 0）。由此消除 INT8 从不产生的 W4A8 专属 fp32 激活常驻（norm/rope）。

---

## 5. Phase 2 显存削减：rope 原生 dtype 旋转 + na concat 缓冲

**提交：** `c43d353`（rope `__ROPE_NO_FP32__`）、`8d6cf36`、`ce4aed3`、`379dfde` — *7b+3b 原地 rotary、去除瞬态全长 cat 缓冲（W4A8 专用路径，INT8/NVFP4 不受影响）*

- **`__ROPE_NO_FP32__`（dit_7b + dit_3b）：** `apply_rotary_emb` 保持输入 dtype（`out.type(dtype)`），强制 `.float()` 只是多分配 q/k 两份全长 fp32 拷贝——实测移除后**峰值 −3.37 GiB**——换来的是舍入级差异（cos 0.999997 vs fp32 路径）。
- **`na.concat` / `concat_idx`：** 去除瞬态全长拼接缓冲，压住 Phase 2 激活峰值。
- 分离原则保持：共通的 `na.py` / `rope.py` 已从 W4A8 专属实验中还原（`379dfde`），INT8 / NVFP4 数值不受 W4A8 分块前向工作影响。

---

## 6. 标准 DiT 加载器新增 norm_bf16 开关

**提交：** `12c2534` — *expose norm_bf16 switch on legacy DiT loader node*；`ebdefe4` — *README 节点文档（EN/zh）+ 截图*

- `norm_bf16` 开关（v1.6.0 起仅 DisTorch2 加载器）现于标准 **`SeedVR2 (Down)Load DiT Model`** 节点同样提供：OFF（默认）= 传统 fp32 norm 路径（质量优先，行为不变）；ON = Phase 2 的 RMS/QK norm 以 bf16 执行，显著节省常驻显存，代价是 bf16 舍入（逐像素 PSNR 约 37–39 dB vs fp32）。
- `video_upscaler.py` 对两种加载器 config 布局以**显式分支分离**读取（DisTorch2：`distorch2.norm_bf16`；标准：顶层 `norm_bf16`），两入口不混读。以实际发布文件抽出的开关块执行 6 场景实测（legacy ON/OFF、d2 ON/OFF、杂散键优先级、键缺失）。
- README（EN + 中文）两版均已补齐标准加载器节点的完整文档节（`ebdefe4`）。
