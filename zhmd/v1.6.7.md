# SeedVR2 Video Upscaler — 版本发布说明 (v1.6.7)

## 概述

SeedVR2 Video Upscaler v1.6.7 彻底根除了在特定非标及竖屏宽高比（如 560×938 的 2 倍超分辨率处理）下，视频画面右边缘（中断断续出现）及右下角出现的棋盘格/点状高频噪声。本次更新深入排查并解决了 **DiT 720P 窗口自注意力切分中的极小残余切片（Runt Window）塌陷** 以及 **TensorRT VAE 跨 CUDA 流异步并发竞态** 两大深层技术缺陷。通过引入自适应安全几何填充与双向 CUDA 流同步屏障，在保持显存近乎零增量（仅 30–50MB）的前提下，实现了任意非标分辨率下的纯净重建。

---

## 1. DiT 720P 窗口自适应安全填充（根除右边缘与右下角棋盘格噪声）

### 缺陷表现与数学根源分析
在对特定分辨率（典型如 `560×938`）进行 2 倍超分辨率处理时，画面右下角以及中段右边缘会规律性出现网格状、棋盘格状的点状杂色高频噪声：

1. **分辨率几何推导**:
   - 输入画面：`560 × 938`
   - 2 倍目标尺寸：`1120 × 1876`（经 8 的倍数下取整对齐为 `1120 × 1872`）
   - VAE 空间（8 倍降采样）：潜空间（Latent）分辨率为 **宽 140 × 高 234**（经常规 16 对齐后高度为 236）
2. **DiT 720P Window Attention 切分机制**:
   - SeedVR2 的 DiT 采用局部窗口自注意力机制（`make_720Pwindows_bysize`），在 1080P/720P 下切分窗口大小通常为 **宽 `ww = 23`，高 `wh = 39`**。
3. **极小残余窗口切片（Runt Window）的产生**:
   - 水平方向切分计算：`140 ÷ 23 = 6`，余数恰好为 **`2`**！
   - 横向切分为 `[0..23], [23..46], [46..69], [69..92], [92..115], [115..138]` 之后，最右侧最后一列（`iw = 6`）被切分为 **`slice(138, 140)` —— 宽度仅为 2 个潜空间像素（对应画面仅 16 像素）的极窄条带**。
   - 纵向同理，最底部也存在余数仅为 2 的切片；右下角则沦为 **2 × 2 像素的孤立点**。
4. **注意力机制崩溃机理**:
   - Window Attention 仅在窗口内部的 Token 之间计算自注意力。当窗口宽度仅有 2 个像素（整行仅 78 个 Token，右下角仅 4 个 Token）时，严重缺乏左侧相邻画面的上下文语义参考。
   - 极小 Token 数量导致 Softmax 注意力归一化与 RoPE（旋转位置编码）剧烈失稳甚至数值溢出，解码后直接在画面边缘还原为高频杂色点与棋盘格。由于整列窗口（纵向 6 段）均存在该残余切片，因此在画面中段右边缘与右下角断续显现。
   - 相对地，标准分辨率（如 1280×720、1920×1080）余数充足（如 19 或 0），因而从未触发该缺陷。

### 自适应安全填充技术方案
在图像输入预处理管线 `src/data/image/transforms/divisible_crop.py`（`DivisiblePad`）中实装动态安全几何判别机制：

```python
# 预先检测 DiT 720P 窗口切分后的残余像素
while True:
    cur_h, cur_w = height + pad_height, width + pad_width
    lat_h, lat_w = cur_h // 8, cur_w // 8
    scale = math.sqrt((45 * 80) / (lat_h * lat_w))
    resized_h, resized_w = round(lat_h * scale), round(lat_w * scale)
    wh, ww = ceil(resized_h / 2), ceil(resized_w / 2)
    rem_h, rem_w = lat_h % wh, lat_w % ww

    need_h = (0 < rem_h < 6)
    need_w = (0 < rem_w < 6)
    if not need_h and not need_w:
        break
    if need_w:
        pad_width += self.width_factor    # 步进 16 像素
    if need_h:
        pad_height += self.height_factor  # 步进 16 像素
```

- **动态裕量补偿**: 当检测到水平或垂直方向的残余潜空间像素处于极小危险区间（`< 6` 潜空间像素，即画面 48 像素以下）时，自适应以 16 像素为单位向右/下追加填充，使最后一个窗口具备充足的邻域上下文，彻底消除孤立残余切片。
- **自动无缝还原裁剪**: 在 Phase 3（VAE 解码）末尾，系统严格依据预先记录的 `true_target_dims` 执行 `sample[:, :, :true_h, :true_w]` 自动裁切，输出视频严格保持原生目标长宽比与像素规格。
- **近乎为零的显存增量**: 仅在右侧/底部追加 16~32 像素边缘填充，面积增幅仅约 2%~4%，显存占用增加仅数十 MB，绝无 OOM 风险；对于本来就整除或余数充分的标准比例，填充增量为 `+0px`。

## 2. TensorRT VAE 跨 CUDA 流显式同步屏障（`wait_stream`）

### 异步并发读写竞态排查
在 TensorRT VAE 解码器（`src/core/trt_decoder.py`）与编码器（`src/core/trt_encoder.py`）中，系统维护了多条并发 CUDA 执行流：
- **调用方流（Caller / Default Stream）**: 负责分配与零初始化累加缓冲区 `result` 与权重掩码 `weights`，并在全部循环结束后执行 `result / weights` 的归一化除法。
- **TensorRT 专属流（TRT Dedicated Stream）**: 负责逐分块执行 TensorRT 引擎异步前向推理 `execute_async_v3`，并将结果累加进 `result`。

此前虽然在单个分块推理后调用了 `stream.synchronize()`，但在**循环开始前**以及**最后一个分块累加至 `result` 之后**，缺失了调用方流与 TensorRT 流之间的双向屏障：
1. **输入准备不同步**: 调用方流的零初始化与 padding 尚未全部在硬件上就绪，TRT 流即可能过早读取输入。
2. **末尾累加竞态**: 最后一个分块（右下角分块）的 `result += ...` 累加操作是在其 `stream.synchronize()` 之后入队的。调用方流未经等待立即进入 `result / weights` 除法，导致右下角分块在权重尚未完全累加（weights 接近 0）时被提前读取并除以 `1e-6`，经 `clamp(±2)` 后放大为随机噪点。

### 双向流同步实现
在编码器与解码器的分块执行循环前后分别插入双向 `wait_stream`：

```python
caller_stream = torch.cuda.current_stream()
stream.wait_stream(caller_stream)  # [前置屏障] 确保 TRT 执行前输入与缓冲区完全就绪

with _DECODE_LOCK, torch.cuda.stream(stream):
    # 分块推断与累加循环...
    ...

caller_stream.wait_stream(stream)  # [后置屏障] 确保最后一个分块结果完全累加完成后再进行除法
decoded = (result / weights.clamp_min(1e-6).to(result.dtype)).clamp(-2.0, 2.0)...
```

GPU 硬件层面的事件驱动同步彻底排除了所有异步竞态隐患，零性能损耗。
