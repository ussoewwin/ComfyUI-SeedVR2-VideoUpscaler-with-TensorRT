# SeedVR2 Video Upscaler — 版本发布说明 (v1.6.9)

## 概述

SeedVR2 Video Upscaler v1.6.9 引入了全链路、系统性的**显存（VRAM）污染消除与深度内存回收架构**。

在复杂的 ComfyUI 工作流中，长时间或大分辨率推理经常因前置节点驻留模型、多阶段批次间张量悬挂以及 PyTorch CUDA Caching Allocator 的内存碎片化，导致可用显存逐步恶化、甚至诱发 Out-Of-Memory（CUDA OOM）崩溃或生成瑕疵。本次更新在管线入口、四大推理阶段的每个批次边界、TensorRT VAE 执行块、以及核心内存管理器中，全面整合了 ComfyUI 原生内存管理与 PyTorch 底层显存同步机制，彻底根除显存污染。

---

## 1. 显存污染根源与技术剖析

在 ComfyUI 环境下，仅依靠 Python 原生的 `del` 或 PyTorch 的 `torch.cuda.empty_cache()` 无法彻底清除显存占用的深层技术原因如下：

1. **ComfyUI 内部模型生命周期追踪脱节**：
   ComfyUI 拥有一套独立的模型管理子系统（`comfy.model_management`）。当工作流中前置节点执行完毕后，相关模型的权重大多仍然被引用并锁定在显存中（以备缓存复用）。如果后续节点没有显式请求驱逐（evict），这些模型权重将持续占用数 GB 的物理显存空间。
2. **PyTorch Caching Allocator 内部碎片化**：
   在频繁分配和释放大张量（如超高分辨率 8K 潜在表示、TensorRT 缓冲区）时，PyTorch 的显存分配器会在显存池中产生大量非连续的微小闲置块。若缺少显式的 `cuda.synchronize()` 屏障与强制垃圾回收协同，这些碎片无法被整合成连续空间，导致看似有剩余显存却无法分配大张量。
3. **管线阶段间（Phase 1 ~ Phase 4）张量未切断**：
   在多批次（Multi-batch）循环中，前一个批次的中间计算变量若未在循环体末尾显式切断引用并触发深度回收，将跨批次残留，导致显存水位随批次递增而阶梯式上升。

---

## 2. 系统性治理架构与实现规范

### 2.1 执行前后 ComfyUI 驻留模型与缓存强制排空（`video_upscaler.py`）

在主节点 `SeedVR2 Video Upscaler` 执行的最先前端（模型加载前）与最终末端（`finally` 资源清理块）中，部署了最高优先级的模型驱逐机制：

```python
# Pre-execution / Post-execution ComfyUI VRAM Pollution Purge
try:
    import comfy.model_management as mm
    mm.cleanup_models_gc()
    mm.cleanup_models()
    mm.soft_empty_cache(force=True)
    if torch.cuda.is_available():
        torch.cuda.synchronize()
except Exception:
    pass
```

- **机制效用**：
  - `mm.cleanup_models_gc()`：强制 ComfyUI 执行内部模型的垃圾回收判定。
  - `mm.cleanup_models()`：立即注销并卸载已被标记为非活跃的前置节点模型。
  - `mm.soft_empty_cache(force=True)`：强制清空 ComfyUI 维护的软缓存池。
  - `torch.cuda.synchronize()`：确保所有异步 CUDA 流释放操作在 GPU 物理端生效完成。

---

### 2.2 全四大管线阶段的逐批次深度显存清洗（`generation_phases.py`）

在 SeedVR2 的核心推理执行管线中，针对全部四个核心处理阶段：
- **Phase 1**：VAE 编码（`encode_all_batches`）
- **Phase 2**：DiT 潜在超分放大（`upscale_all_batches`）
- **Phase 3**：VAE 解码（`decode_all_batches`）
- **Phase 4**：最终视频后处理组装（`postprocess_all_batches`）

在每一个批次循环（Batch loop）的结尾处，强制执行四阶深度清理序列：

```python
# 批次边界深度清理序列
import gc as _gc
_gc.collect()
if torch.cuda.is_available():
    try:
        import comfy.model_management as mm
        mm.soft_empty_cache(force=True)
    except Exception:
        pass
    torch.cuda.synchronize()
    torch.cuda.empty_cache()
```

- **机制效用**：
  彻底隔离批次之间的内存状态。即使在超长视频或极高分辨率多批次推理下，显存水位在每个批次结束后均被重置回基线水平，完全杜绝阶梯式显存泄漏。

---

### 2.3 TensorRT VAE 与 ComfyUI 内存管理器深度协同（`trt_decoder.py` / `trt_encoder.py`）

TensorRT 引擎在执行空间分块（Tiling）推理时，需要频繁在专属 CUDA 流与 PyTorch 主流之间流转显存。我们在每个 Chunk 处理完成后，将两套显存释放通道深度打通：

```python
# trt_decoder.py & trt_encoder.py 块后清理
del source, result, weights
import gc as _gc
_gc.collect()
if torch.cuda.is_available():
    try:
        import comfy.model_management as mm
        mm.soft_empty_cache(force=True)
    except Exception:
        pass
    torch.cuda.synchronize()
    torch.cuda.empty_cache()
```

- **机制效用**：
  显式切断累加器张量引用，并在调用 `torch.cuda.empty_cache()` 前后与 ComfyUI 的 `soft_empty_cache` 进行硬件级栅栏同步，防止 TRT 与 ComfyUI 在分块交替时互相污染显存池。

---

### 2.4 核心通用内存管理器统一集成（`memory_manager.py`）

全局通用内存释放函数 `clear_memory()` 现已深度整合 ComfyUI 软缓存清理：

```python
if is_cuda_available():
    try:
        import comfy.model_management as mm
        mm.soft_empty_cache(force=True)
    except Exception:
        pass
    torch.cuda.synchronize()
    torch.cuda.empty_cache()
    torch.cuda.ipc_collect()
```
